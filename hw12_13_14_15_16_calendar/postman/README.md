# Calendar — Postman

## Импорт и запуск

1. В Postman нажми **Import** и выбери `calendar.postman_collection.json` из этой папки.
2. В переменных коллекции проверь `baseUrl`: по умолчанию `http://localhost:8080`, как в `configs/config.yaml`. Адрес указывается без завершающего слеша.
3. Запусти календарь с подходящей конфигурацией и доступным хранилищем. Для запуска из корня проекта: `go run ./cmd/calendar --config ./configs/config.yaml`. Для PostgreSQL должны быть настроены параметры подключения.
4. Открой **Run collection** и выполни все папки в указанном порядке, **одну итерацию**, без параллельного запуска. Коллекция создаёт реальные события в выбранном хранилище.

## Сценарии

- **01 CRUD lifecycle**: hello → создание → получение по дню, неделе, месяцу → полное обновление → проверка сохранённых изменений → удаление → проверка отсутствия. ID сохраняется в `eventId` автоматически. Для ручного запуска сначала выполни Create event.
- **02 Period boundaries**: события на границах дня, недели и месяца; запрос недели по пятнице и воскресенью; запрос месяца по его середине; високосный февраль. Время фикстур задано в UTC, как и разбор даты в текущем HTTP-слое.
- **03 Boundary cleanup**: удаление девяти событий предыдущей папки по сохранённым ID. После остановленного запуска выполни эту папку вручную до нового запуска. Событие CRUD удаляется в своей папке; при остановке до удаления выполни Delete event вручную.
- **04 Invalid requests**: отсутствующая и невозможная дата во всех трёх методах, удаление без ID, некорректный JSON при создании.

Всего 40 запросов. Новые события получают случайные UUID пользователей, чтобы не конфликтовать с существующими событиями. Проверки списков ищут ID созданных событий и не требуют пустого хранилища. Авторизация не используется.

## Проверяемый контракт

- `POST /event`, `PUT /event`: 200 и JSON объекта события. При обновлении передаются все поля.
- `DELETE /event?id=...`: 202.
- `GET /event/day|week|month?date=YYYY-MM-DD`: 200 и JSON-массив; пустая выборка — 204.
- Неделя: понедельник 00:00 включительно — следующий понедельник исключительно. Месяц: первое число включительно — первое число следующего месяца исключительно. Отбор выполняется по времени начала события.
- Некорректный JSON, отсутствующие обязательные параметры и невозможная дата: 400.

## Замеченные препятствия в текущем приложении

Коллекция не меняет код приложения и не маскирует ошибки проверками на неправильные ответы:

- В `internal/transport/http/server.go` GET-шаблоны `GET event/day`, `GET event/week`, `GET event/month` не содержат начального `/`. В Go ServeMux такие строки интерпретируются с ограничением по host (`event`), поэтому запросы коллекции на `/event/...` не попадут в нужные обработчики.
- В `handler.go` указан layout `2006-01-01`: в Go день обозначается `02`, поэтому для формата `YYYY-MM-DD` нужен layout `2006-01-02`. Текущий layout неправильно разбирает даты.
- Непустые списки в `handler.go` записываются через `fmt.Fprintf(w, "%v", wrapper.Resp)`, что не формирует JSON-массив. Проверки JSON обнаружат это после исправления маршрутов.
- При отсутствующих параметрах или неверной дате некоторые обработчики пишут тело до `WriteHeader(400)`. Первый вызов Write фиксирует статус 200, поэтому проверки ожидаемого 400 будут падать.

Пока эти проблемы остаются, зелёный прогон всей коллекции не ожидается. Работоспособность API подтверждает только запуск против реально работающего сервера; локальная проверка файлов коллекции не заменяет такой прогон.
