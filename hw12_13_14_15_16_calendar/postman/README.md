# Calendar — Postman

Коллекции проверяют основной функционал календаря: создание события, получение списков по дню, неделе и месяцу, обновление и удаление. После обновления проверяется сохранение изменений, после удаления — отсутствие события в списке.

## HTTP API

1. В Postman нажми **Import** и выбери `calendar.postman_collection.json` из этой папки.
2. Проверь переменную коллекции `baseUrl`: по умолчанию `http://localhost:8080`, без завершающего слеша.
3. Запусти календарь с подходящей конфигурацией и доступным хранилищем: `go run ./cmd/calendar --config ./configs/config.yaml`. Для PostgreSQL должны быть настроены параметры подключения.
4. Открой **Run collection** и выполни папку **01 CRUD lifecycle** по порядку, одну итерацию, без параллельного запуска.

Всего 9 запросов, включая `GET /hello`. Запрос создания генерирует случайный UUID пользователя и сохраняет ID события в `eventId`. Для ручного запуска сначала выполни `02 Create event`.

Создание, обновление и получение списков ожидают HTTP 200; удаление — 202. При проверке удаления допускается пустой список с HTTP 204. При обновлении передаются все поля события.

Если прогон прерван до удаления, выполни `08 Delete event` с сохранённым `eventId` перед новым прогоном.
